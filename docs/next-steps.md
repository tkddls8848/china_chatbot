# 계획: 리서치·시장 컨센서스를 웹으로 연다

봇이 이미 만들고 있는 두 산출물 — **리서치 결과**와 **시장 컨센서스(국가별 감성
+ Polymarket 패널)** — 를 브라우저에서 볼 수 있게 하는 작업의 계획서다. 앞으로 할
로컬 작업은 여기 모은다. 서버를 상대로 하는 상시 절차는 `docs/aws-next-steps.md`,
인스턴스 생성·전환은 `iac/terraform/README.md`다.

## 0. 확정된 방향 (2026-08-19)

| 축 | 결정 | 따라오는 제약 |
|---|---|---|
| 사용자 | 나 + 지인. **읽기 전용 공개** | 도메인·HTTPS·로그인은 붙이되 회원가입·계정별 상태는 만들지 않는다 |
| 봇 | **존치.** 웹은 같은 상태를 읽는 두 번째 표면 | 수집·번역·스케줄은 지금 그대로 봇이 한다 |
| 호스팅 | **현 Lightsail `micro_3_0`에 얹는다** | 1GB RAM, 2 vCPU × baseline 10% = 하루 4.8 vCPU-hour |

**실행 트리거는 웹에 열지 않는다.** `/research run`, `/market` 재계산처럼 LLM을
부르는 경로는 텔레그램(=나)에만 둔다. 이유는 두 가지고 둘 다 양보할 수 없다.

- **Neurons.** 무료 한도는 하루 10,000이고 뉴스 번역이 대부분을 쓴다. 웹에서
  누구나 실행을 누를 수 있으면 남은 예산이 링크를 받은 사람 수만큼 곱해져 나간다.
  소진되면 그날 남은 시간 동안 `/research`와 `/market`이 **봇에서도** 막힌다.
- **상태.** 리서치 상태(`data/research/market_research.json`)는 단일 사용자
  형식이다. 주제(`sight`)와 이력(`history`)이 하나뿐이라 두 사람이 동시에 실행하면
  서로의 맥락을 덮는다. 계정별로 나누는 것은 멀티테넌시이고 이번 범위가 아니다.

즉 웹은 **이미 계산된 것을 보여주는 창**이다. 이 한 줄이 아래 설계 전부를 정한다.

## 1. 지금 있는 것

`app/webadmin/server.py`(432줄)에 FastAPI 앱이 이미 있다. 봇 프로세스 **안에서**
uvicorn을 백그라운드 태스크로 띄우고(`start_web_admin`), 봇과 이벤트 루프를
공유한다. 동기 파일 읽기는 `asyncio.to_thread`로 넘긴다 — 루프를 막으면 텔레그램
폴링까지 멈추기 때문이다.

| 항목 | 현재 |
|---|---|
| 라우트 | `/`(대시보드 HTML 인라인), `/api/status`, `/api/watchlist`(GET·POST·DELETE), `/api/news`, `/api/events`, `/api/research`, `/api/predictions` |
| 인증 | HTTP Basic 1계정 (`WEB_ADMIN_USER`/`WEB_ADMIN_PASSWORD`) |
| 바인딩 | `127.0.0.1:8787` |
| 노출 | **없음.** 방화벽은 22만 열려 있고 접근은 SSH 터널뿐 |
| 데이터 접근 | `bot_data`의 매니저 우선, 기능이 꺼져 있으면 파일 직접 읽기 폴백 |

**이걸 그대로 공개하지 않는다.** 관심종목 쓰기 API가 열려 있고, Basic 자격증명이
평문으로 오가며, 무엇보다 공개 트래픽이 봇의 이벤트 루프를 직접 밟는다.
관리 웹은 지금의 역할(터널 전용 관리 도구)로 남기고, 공개용은 따로 세운다.

## 2. 예산

| 자원 | 총량 | 이미 쓰는 곳 | 웹이 쓸 수 있는 몫 |
|---|---|---|---|
| 지속 CPU | 4.8 vCPU-h/일 | 사전선별 보정 3.6h(75%) + 봇 상시 | **1.2h 중 일부** |
| 메모리 | 1GB + 스왑 2G | 봇(pandas·matplotlib 상주) | 여유가 크지 않다 |
| Neurons | 10,000/일 | 뉴스 번역이 대부분 | **웹은 0** |
| 대역폭 | 번들 포함분 | 미미 | PNG 크기가 사실상 전부 |

**matplotlib 렌더가 이 예산에서 가장 비싼 단일 동작이다.** `render_market_chart`는
12×7.5인치 figure를 dpi 160으로 굽는다. 요청마다 굽는 구조로 만들면 지인 몇 명이
새로고침하는 것만으로 사전선별 보정이 밀린다. 그래서 3-2가 필요하다.

## 3. 설계 결정

### 3-1. 공개 웹은 봇과 **다른 프로세스**로 띄운다

같은 프로세스에 얹으면 공개 요청 하나가 텔레그램 폴링과 뉴스 주기를 붙잡는다.
읽기 전용이라 `bot_data` 매니저가 필요 없으므로 분리 비용도 작다 — 파일만 읽으면
된다.

- 새 진입점 `app/webpub.py`(가칭)와 별도 systemd 유닛 `stock-chatbot-web`.
- `127.0.0.1:8788` 바인딩. 8787(관리)과 포트를 나눠 권한도 나눈다.
- 봇이 죽어도 웹은 마지막 산출물을 계속 보여준다(반대도 같다).
- 상태 파일은 **읽기만** 한다. 웹이 `data/`에 쓰지 않으므로 원자적 쓰기 규약과
  충돌하지 않는다.

### 3-2. 화면은 요청 때 만들지 않고 **미리 구워 둔다**

봇이 산출물을 갱신하는 시점에 `data/webpub/`으로 굽고, 웹은 그 파일을 그대로
내보낸다. 렌더 비용이 방문자 수와 무관해지고, 웹 프로세스는 파일 서빙만 하므로
CPU가 거의 들지 않는다.

| 산출물 | 언제 굽나 | 무엇 |
|---|---|---|
| `market_chart.png` | 시장 감성 갱신 후 (하루 몇 회) | `render_market_chart`의 결과 |
| `market.json` | 같은 시점 | 국가별 점수·기사 수·순위, Polymarket 패널 시계열 |
| `research.json` | `/research run` 완료 후 | `last_result` 전체 + `history` 압축본 + `sight` |
| `meta.json` | 위 셋과 함께 | 각 산출물의 생성 시각, 봇 버전 |

굽는 코드는 `core/storage.py`의 원자적 쓰기를 쓴다(반쯤 쓰인 PNG를 웹이 읽는 일이
없어야 한다). 시각은 `core/clock.py`의 `now()`만 쓴다.

**`/market`의 오늘분은 호출 때 다시 계산된다**(완료된 과거 일자만 저장분 재사용).
웹이 그 재계산을 촉발하면 안 되므로, 웹은 마지막으로 구워진 파일을 보여주고
`meta.json`의 생성 시각을 화면에 함께 적는다. "지금 이 순간"이 아니라 "언제
기준"인지 보이면 된다.

### 3-3. 노출은 리버스 프록시 + TLS, 인증은 한 겹 유지

| 항목 | 선택 | 왜 |
|---|---|---|
| 프록시 | Caddy | 인증서 발급·갱신이 자동이다. nginx + certbot은 갱신 cron을 따로 관리해야 한다 |
| 포트 | 443만 연다. 80은 리다이렉트용으로만 | `manage_firewall = true`이므로 `main.tf`의 `port_info`에 추가한다 |
| 도메인 | 필요. 고정 IP는 이미 있다 | 인증서 발급 조건 |
| 인증 | TLS 위의 Basic 1계정(공유 비밀번호) | 지인 소수 대상이고 읽기 전용이다. 계정 관리를 만들 이유가 없다 |
| 관리 웹 | 8787은 **계속 닫아 둔다** | 쓰기 API가 있는 쪽은 터널로만 접근한다 |

**방화벽을 열기 전에 3-1과 3-2가 먼저 끝나 있어야 한다.** 순서를 뒤집으면 공개
트래픽이 봇 프로세스로 바로 들어간다.

### 3-4. 웹은 GET만 가진다

공개 앱에는 쓰기 라우트를 만들지 않는다. 관심종목 추가·삭제는 관리 웹(8787)과
텔레그램에 그대로 남는다. "읽기 전용"을 앱 계층에서 지키면, 인증이 새더라도
잃는 것이 열람뿐이다.

## 4. 화면

세 페이지면 충분하다. SPA 프레임워크를 들이지 않고, 지금 관리 대시보드처럼 서버가
HTML을 내보내고 필요한 곳만 fetch로 채운다.

1. **시장 컨센서스** — `market_chart.png` 한 장, 국가별 점수 표, Polymarket 패널이
   승격됐다면 그 아래 별도 섹션(축이 다르므로 **합산하거나 같은 그래프에 얹지
   않는다**). 하단에 "기준 시각"과 "이 값이 무엇이 아닌지" 한 줄.
2. **리서치** — 현재 주제(`sight`), 마지막 전체 결과(`last_result`), 이력 요약.
   `history`는 프롬프트용 압축본이고 `last_result`가 화면용 전체다 — 둘을 합치지
   않는다(합치면 프롬프트가 비대해지거나 화면이 얇아진다).
3. **정보** — 데이터 출처, 갱신 주기, 면책. 개인 운영 봇의 산출물이고 투자 조언이
   아니라는 문장을 여기 둔다.

## 5. 단계

각 단계는 **그 단계까지만 하고 멈춰도 안전한** 상태로 끝난다.

### 0단계 — 로컬 환경을 현재 기준에 맞춘다

로컬 `.env`는 2026-08-11 값이다. **명시값이 코드 기본값을 이기므로** 지금 로컬에서
봇을 켜면 옛 동작을 본다. 서버와 다른 설정으로 재현하게 되는 것이 실제 비용이다.

| 키 | 로컬 `.env` | 현재 기준 |
|---|---:|---:|
| `FEATURES_ENABLED` | `news_prefilter` 없음 | 있음 |
| `NEWS_SOURCE_ARTICLE_LIMIT` | 30 | 250 |
| `SCHEDULER_INTERVAL_MINUTES` | 20 | 60 |
| `NEWS_DIGEST_SEND_LIMIT` | 3 | 2 |

`NEWS_PREFILTER_MODE`와 `NEWS_NIGHT_*`는 로컬에 없고 코드 기본값이 먹는다 —
없는 키를 새로 넣지 않는다.

```powershell
.\venv\Scripts\python.exe -c "import sys; sys.path.insert(0,'app'); import core.config"
```

로컬 봇을 켤 때는 서버와 같은 토큰이므로 **한쪽만 켠다.**

*완료 기준*: 위 명령이 오류 없이 끝나고 `.env`의 네 값이 표와 같다.

### 1단계 — 산출물을 굽는다 (웹 없이)

봇 안에 굽는 코드만 넣는다. 아직 아무도 읽지 않으므로 되돌리기 쉽다.

- `data/webpub/`에 `market.json`·`market_chart.png`·`research.json`·`meta.json`.
- 굽는 시점은 기존 갱신 경로에 붙인다(시장 감성 갱신 후, 리서치 실행 후).
- 실패해도 봇의 본래 동작을 막지 않는다 — 소스 단위 격리와 같은 원칙이다.
- `FEATURES_ENABLED`에 새 키를 만들지 않는다. 이건 기존 기능의 부수 출력이다.

*완료 기준*: 로컬에서 봇을 한 주기 돌리면 네 파일이 생기고, `meta.json`의 시각이
`clock.now()` 기준 KST이며, 관련 테스트와 전체 pytest·ruff가 통과한다.

### 2단계 — 읽기 전용 웹 프로세스

- `app/webpub.py` + FastAPI 앱. GET 라우트만. `data/webpub/`만 읽는다.
- 로컬에서 `127.0.0.1:8788`로 띄워 세 화면을 완성한다.
- 이 시점에도 노출은 없다. 서버에 올리면 SSH 터널로 본다.

*완료 기준*: 봇을 끈 상태에서도 세 화면이 마지막 산출물로 그려진다(프로세스 분리가
실제로 됐다는 증거다).

### 3단계 — 서버에 올리고 터널로 확인

- systemd 유닛 `stock-chatbot-web` 추가. 봇 유닛과 마찬가지로
  `WorkingDirectory`는 `app/`, `MPLBACKEND=Agg`.
- 부트스트랩(`user_data.sh.tftpl`)에도 같은 유닛을 넣는다. 단 `user_data` 변경은
  기존 인스턴스에 반영되지 않으므로(`ignore_changes`), 서버에는 SSH로 직접 설치한다.
- 며칠 돌리며 `uptime`과 메모리를 본다.

*완료 기준*: 터널로 세 화면이 열리고, 사전선별 로그에 `중단=budget`이 새로 늘지
않으며, `free -h`의 여유가 배포 전과 유의미하게 다르지 않다.

### 4단계 — 공개

- 도메인을 고정 IP에 연결한다.
- Caddy 설치, 443 → `127.0.0.1:8788` 프록시, Basic 인증.
- `main.tf`의 `port_info`에 80·443을 추가하고 `apply`.
- 링크와 비밀번호를 지인에게 전달한다.

*완료 기준*: 외부 회선에서 HTTPS로 열리고, 8787은 여전히 밖에서 닫혀 있으며,
인증서 자동 갱신이 한 번 이상 성공한다.

## 6. 하지 않기로 한 것

되살리자는 이야기가 나올 때 여기를 먼저 본다.

- **회원가입·계정별 상태.** 상태 파일이 단일 사용자 형식이다. 계정 축을 넣으려면
  리서치·관심종목·발송 이력을 전부 다시 짜야 한다. 이번 범위가 아니다.
- **웹에서 LLM 실행.** 0절의 두 이유(Neurons, 상태 단일성) 때문이다.
- **DB 도입.** 산출물은 파일 넷이고 조회는 전부 "마지막 것 한 개"다. 인덱스가
  필요한 질의가 없다.
- **SPA 프레임워크·빌드 파이프라인.** 1GB 인스턴스에 Node 툴체인을 얹을 이유가
  화면 셋에는 없다.
- **관리 웹(8787) 공개.** 쓰기 API가 있는 쪽은 터널로만 연다.
- **실시간 갱신(WebSocket·폴링).** 데이터가 분 단위로 바뀌지 않는다. 기준 시각을
  적는 것으로 충분하다.

## 7. 위험과 중단 기준

| 위험 | 신호 | 조치 |
|---|---|---|
| 웹이 CPU 예산을 먹는다 | 사전선별 `중단=budget`이 매일 나온다 | 3단계에서 멈추고 굽는 주기를 줄인다 |
| 메모리 압박 | 스왑 사용이 상시, OOM kill | 웹 프로세스를 봇과 같은 인스턴스에서 뺀다(= 호스팅 결정 재검토) |
| 공개 후 남용 | 접근 로그가 지인 수와 맞지 않는다 | 비밀번호 교체. 그래도 계속되면 443을 닫고 터널로 되돌린다 |
| 산출물이 낡는다 | `meta.json` 시각이 하루 이상 밀린다 | 봇 쪽 굽기 경로가 실패하고 있다. 로그를 본다 |

**4단계까지 가지 않아도 실패가 아니다.** 2단계(터널로 보는 읽기 전용 웹)만으로도
지금보다 낫고, 그 상태로 멈추면 공개에 따르는 위험이 전부 사라진다. 공개는 화면이
쓸 만하다는 확신이 선 뒤에 한다.
