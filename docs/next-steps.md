# 계획: 리서치·시장 컨센서스를 웹으로 연다

봇이 이미 만들고 있는 두 산출물 — **리서치 결과**와 **시장 컨센서스(국가별 감성
+ Polymarket 패널)** — 를 브라우저에서 볼 수 있게 하는 작업의 계획서다. 앞으로 할
로컬 작업은 여기 모은다. 서버를 상대로 하는 상시 절차는 `docs/server-ops.md`,
인스턴스 생성·전환은 `iac/terraform/README.md`다.

**이 파일에는 계획이 둘 있다.** 이 문서(1~7절)는 웹 공개이고, 아래 `A`절부터는
봇 쪽 새 기능인 **세력 행동 추정**이다. 둘은 서로를 기다리지 않는다 — 다만 세력
추정의 산출물을 웹에 올리는 것은 A-8의 승격 게이트를 통과한 뒤의 일이다.

## 0. 확정된 방향 (2026-08-19)

| 축 | 결정 | 따라오는 제약 |
|---|---|---|
| 사용자 | 나 + 지인. **읽기 전용 공개** | 도메인·HTTPS·로그인은 붙이되 회원가입·계정별 상태는 만들지 않는다 |
| 봇 | **존치.** 웹은 같은 상태를 읽는 두 번째 표면 | 수집·번역·스케줄은 지금 그대로 봇이 한다 |
| 호스팅 | **현 Lightsail `micro_3_0`에 얹는다** | 1GB RAM, 2 vCPU × baseline 10% = 하루 4.8 vCPU-hour |

**실행 트리거는 웹에 열지 않는다.** `/research run`, `/market` 재계산처럼 LLM을
부르는 경로는 텔레그램(=나)에만 둔다. 이유는 두 가지고 둘 다 양보할 수 없다.

- **Neurons.** 무료 한도는 하루 10,000이고 뉴스 번역이 대부분을 쓴다. 웹에서
  누구나 실행을 누를 수 있으면 남은 예산이 링크를 받은 사람 수만큼 곱해져 나간다.
  소진되면 그날 남은 시간 동안 `/research`와 `/market`이 **봇에서도** 막힌다.
- **상태.** 리서치 상태(`data/research/market_research.json`)는 단일 사용자
  형식이다. 주제(`sight`)와 이력(`history`)이 하나뿐이라 두 사람이 동시에 실행하면
  서로의 맥락을 덮는다. 계정별로 나누는 것은 멀티테넌시이고 이번 범위가 아니다.

즉 웹은 **이미 계산된 것을 보여주는 창**이다. 이 한 줄이 아래 설계 전부를 정한다.

## 1. 지금 있는 것

`app/webadmin/server.py`(432줄)에 FastAPI 앱이 이미 있다. 봇 프로세스 **안에서**
uvicorn을 백그라운드 태스크로 띄우고(`start_web_admin`), 봇과 이벤트 루프를
공유한다. 동기 파일 읽기는 `asyncio.to_thread`로 넘긴다 — 루프를 막으면 텔레그램
폴링까지 멈추기 때문이다.

| 항목 | 현재 |
|---|---|
| 라우트 | `/`(대시보드 HTML 인라인), `/api/status`, `/api/watchlist`(GET·POST·DELETE), `/api/news`, `/api/events`, `/api/research`, `/api/predictions` |
| 인증 | HTTP Basic 1계정 (`WEB_ADMIN_USER`/`WEB_ADMIN_PASSWORD`) |
| 바인딩 | `127.0.0.1:8787` |
| 노출 | **없음.** 방화벽은 22만 열려 있고 접근은 SSH 터널뿐 |
| 데이터 접근 | `bot_data`의 매니저 우선, 기능이 꺼져 있으면 파일 직접 읽기 폴백 |

**이걸 그대로 공개하지 않는다.** 관심종목 쓰기 API가 열려 있고, Basic 자격증명이
평문으로 오가며, 무엇보다 공개 트래픽이 봇의 이벤트 루프를 직접 밟는다.
관리 웹은 지금의 역할(터널 전용 관리 도구)로 남기고, 공개용은 따로 세운다.

## 2. 예산

| 자원 | 총량 | 이미 쓰는 곳 | 웹이 쓸 수 있는 몫 |
|---|---|---|---|
| 지속 CPU | 4.8 vCPU-h/일 | 사전선별 보정 3.6h(75%) + 봇 상시 | **1.2h 중 일부** |
| 메모리 | 1GB + 스왑 2G | 봇(pandas·matplotlib 상주) | 여유가 크지 않다 |
| Neurons | 10,000/일 | 뉴스 번역이 대부분 | **웹은 0** |
| 대역폭 | 번들 포함분 | 미미 | PNG 크기가 사실상 전부 |

**matplotlib 렌더가 이 예산에서 가장 비싼 단일 동작이다.** `render_market_chart`는
12×7.5인치 figure를 dpi 160으로 굽는다. 요청마다 굽는 구조로 만들면 지인 몇 명이
새로고침하는 것만으로 사전선별 보정이 밀린다. 그래서 3-2가 필요하다.

## 3. 설계 결정

### 3-1. 공개 웹은 봇과 **다른 프로세스**로 띄운다

같은 프로세스에 얹으면 공개 요청 하나가 텔레그램 폴링과 뉴스 주기를 붙잡는다.
읽기 전용이라 `bot_data` 매니저가 필요 없으므로 분리 비용도 작다 — 파일만 읽으면
된다.

- 새 진입점 `app/webpub.py`(가칭)와 별도 systemd 유닛 `stock-chatbot-web`.
- `127.0.0.1:8788` 바인딩. 8787(관리)과 포트를 나눠 권한도 나눈다.
- 봇이 죽어도 웹은 마지막 산출물을 계속 보여준다(반대도 같다).
- 상태 파일은 **읽기만** 한다. 웹이 `data/`에 쓰지 않으므로 원자적 쓰기 규약과
  충돌하지 않는다.

### 3-2. 화면은 요청 때 만들지 않고 **미리 구워 둔다**

봇이 산출물을 갱신하는 시점에 `data/webpub/`으로 굽고, 웹은 그 파일을 그대로
내보낸다. 렌더 비용이 방문자 수와 무관해지고, 웹 프로세스는 파일 서빙만 하므로
CPU가 거의 들지 않는다.

| 산출물 | 언제 굽나 | 무엇 |
|---|---|---|
| `market_chart.png` | 시장 감성 갱신 후 (하루 몇 회) | `render_market_chart`의 결과 |
| `market.json` | 같은 시점 | 국가별 점수·기사 수·순위, Polymarket 패널 시계열 |
| `research.json` | `/research run` 완료 후 | `last_result` 전체 + `history` 압축본 + `sight` |
| `meta.json` | 위 셋과 함께 | 각 산출물의 생성 시각, 봇 버전 |

굽는 코드는 `core/storage.py`의 원자적 쓰기를 쓴다(반쯤 쓰인 PNG를 웹이 읽는 일이
없어야 한다). 시각은 `core/clock.py`의 `now()`만 쓴다.

**`/market`의 오늘분은 호출 때 다시 계산된다**(완료된 과거 일자만 저장분 재사용).
웹이 그 재계산을 촉발하면 안 되므로, 웹은 마지막으로 구워진 파일을 보여주고
`meta.json`의 생성 시각을 화면에 함께 적는다. "지금 이 순간"이 아니라 "언제
기준"인지 보이면 된다.

### 3-3. 노출은 리버스 프록시 + TLS, 인증은 한 겹 유지

| 항목 | 선택 | 왜 |
|---|---|---|
| 프록시 | Caddy | 인증서 발급·갱신이 자동이다. nginx + certbot은 갱신 cron을 따로 관리해야 한다 |
| 포트 | 443만 연다. 80은 리다이렉트용으로만 | `manage_firewall = true`이므로 `main.tf`의 `port_info`에 추가한다 |
| 도메인 | 필요. 고정 IP는 이미 있다 | 인증서 발급 조건 |
| 인증 | TLS 위의 Basic 1계정(공유 비밀번호) | 지인 소수 대상이고 읽기 전용이다. 계정 관리를 만들 이유가 없다 |
| 관리 웹 | 8787은 **계속 닫아 둔다** | 쓰기 API가 있는 쪽은 터널로만 접근한다 |

**방화벽을 열기 전에 3-1과 3-2가 먼저 끝나 있어야 한다.** 순서를 뒤집으면 공개
트래픽이 봇 프로세스로 바로 들어간다.

### 3-4. 웹은 GET만 가진다

공개 앱에는 쓰기 라우트를 만들지 않는다. 관심종목 추가·삭제는 관리 웹(8787)과
텔레그램에 그대로 남는다. "읽기 전용"을 앱 계층에서 지키면, 인증이 새더라도
잃는 것이 열람뿐이다.

## 4. 화면

세 페이지면 충분하다. SPA 프레임워크를 들이지 않고, 지금 관리 대시보드처럼 서버가
HTML을 내보내고 필요한 곳만 fetch로 채운다.

1. **시장 컨센서스** — `market_chart.png` 한 장, 국가별 점수 표, Polymarket 패널이
   승격됐다면 그 아래 별도 섹션(축이 다르므로 **합산하거나 같은 그래프에 얹지
   않는다**). 하단에 "기준 시각"과 "이 값이 무엇이 아닌지" 한 줄.
2. **리서치** — 현재 주제(`sight`), 마지막 전체 결과(`last_result`), 이력 요약.
   `history`는 프롬프트용 압축본이고 `last_result`가 화면용 전체다 — 둘을 합치지
   않는다(합치면 프롬프트가 비대해지거나 화면이 얇아진다).
3. **정보** — 데이터 출처, 갱신 주기, 면책. 개인 운영 봇의 산출물이고 투자 조언이
   아니라는 문장을 여기 둔다.

## 5. 단계

각 단계는 **그 단계까지만 하고 멈춰도 안전한** 상태로 끝난다.

### 0단계 — 로컬 환경을 현재 기준에 맞춘다

로컬 `.env`는 2026-08-11 값이다. **명시값이 코드 기본값을 이기므로** 지금 로컬에서
봇을 켜면 옛 동작을 본다. 서버와 다른 설정으로 재현하게 되는 것이 실제 비용이다.

| 키 | 로컬 `.env` | 현재 기준 |
|---|---:|---:|
| `FEATURES_ENABLED` | `news_prefilter` 없음 | 있음 |
| `NEWS_SOURCE_ARTICLE_LIMIT` | 30 | 250 |
| `SCHEDULER_INTERVAL_MINUTES` | 20 | 60 |
| `NEWS_DIGEST_SEND_LIMIT` | 3 | 2 |

`NEWS_PREFILTER_MODE`와 `NEWS_NIGHT_*`는 로컬에 없고 코드 기본값이 먹는다 —
없는 키를 새로 넣지 않는다.

```powershell
.\venv\Scripts\python.exe -c "import sys; sys.path.insert(0,'app'); import core.config"
```

로컬 봇을 켤 때는 서버와 같은 토큰이므로 **한쪽만 켠다.**

*완료 기준*: 위 명령이 오류 없이 끝나고 `.env`의 네 값이 표와 같다.

### 1단계 — 산출물을 굽는다 (웹 없이)

봇 안에 굽는 코드만 넣는다. 아직 아무도 읽지 않으므로 되돌리기 쉽다.

- `data/webpub/`에 `market.json`·`market_chart.png`·`research.json`·`meta.json`.
- 굽는 시점은 기존 갱신 경로에 붙인다(시장 감성 갱신 후, 리서치 실행 후).
- 실패해도 봇의 본래 동작을 막지 않는다 — 소스 단위 격리와 같은 원칙이다.
- `FEATURES_ENABLED`에 새 키를 만들지 않는다. 이건 기존 기능의 부수 출력이다.

*완료 기준*: 로컬에서 봇을 한 주기 돌리면 네 파일이 생기고, `meta.json`의 시각이
`clock.now()` 기준 KST이며, 관련 테스트와 전체 pytest·ruff가 통과한다.

### 2단계 — 읽기 전용 웹 프로세스

- `app/webpub.py` + FastAPI 앱. GET 라우트만. `data/webpub/`만 읽는다.
- 로컬에서 `127.0.0.1:8788`로 띄워 세 화면을 완성한다.
- 이 시점에도 노출은 없다. 서버에 올리면 SSH 터널로 본다.

*완료 기준*: 봇을 끈 상태에서도 세 화면이 마지막 산출물로 그려진다(프로세스 분리가
실제로 됐다는 증거다).

### 3단계 — 서버에 올리고 터널로 확인

- systemd 유닛 `stock-chatbot-web` 추가. 봇 유닛과 마찬가지로
  `WorkingDirectory`는 `app/`, `MPLBACKEND=Agg`.
- 부트스트랩(`user_data.sh.tftpl`)에도 같은 유닛을 넣는다. 단 `user_data` 변경은
  기존 인스턴스에 반영되지 않으므로(`ignore_changes`), 서버에는 SSH로 직접 설치한다.
- 며칠 돌리며 `uptime`과 메모리를 본다.

*완료 기준*: 터널로 세 화면이 열리고, 사전선별 로그에 `중단=budget`이 새로 늘지
않으며, `free -h`의 여유가 배포 전과 유의미하게 다르지 않다.

### 4단계 — 공개

- 도메인을 고정 IP에 연결한다.
- Caddy 설치, 443 → `127.0.0.1:8788` 프록시, Basic 인증.
- `main.tf`의 `port_info`에 80·443을 추가하고 `apply`.
- 링크와 비밀번호를 지인에게 전달한다.

*완료 기준*: 외부 회선에서 HTTPS로 열리고, 8787은 여전히 밖에서 닫혀 있으며,
인증서 자동 갱신이 한 번 이상 성공한다.

## 6. 하지 않기로 한 것

되살리자는 이야기가 나올 때 여기를 먼저 본다.

- **회원가입·계정별 상태.** 상태 파일이 단일 사용자 형식이다. 계정 축을 넣으려면
  리서치·관심종목·발송 이력을 전부 다시 짜야 한다. 이번 범위가 아니다.
- **웹에서 LLM 실행.** 0절의 두 이유(Neurons, 상태 단일성) 때문이다.
- **DB 도입.** 산출물은 파일 넷이고 조회는 전부 "마지막 것 한 개"다. 인덱스가
  필요한 질의가 없다.
- **SPA 프레임워크·빌드 파이프라인.** 1GB 인스턴스에 Node 툴체인을 얹을 이유가
  화면 셋에는 없다.
- **관리 웹(8787) 공개.** 쓰기 API가 있는 쪽은 터널로만 연다.
- **실시간 갱신(WebSocket·폴링).** 데이터가 분 단위로 바뀌지 않는다. 기준 시각을
  적는 것으로 충분하다.

## 7. 위험과 중단 기준

| 위험 | 신호 | 조치 |
|---|---|---|
| 웹이 CPU 예산을 먹는다 | 사전선별 `중단=budget`이 매일 나온다 | 3단계에서 멈추고 굽는 주기를 줄인다 |
| 메모리 압박 | 스왑 사용이 상시, OOM kill | 웹 프로세스를 봇과 같은 인스턴스에서 뺀다(= 호스팅 결정 재검토) |
| 공개 후 남용 | 접근 로그가 지인 수와 맞지 않는다 | 비밀번호 교체. 그래도 계속되면 443을 닫고 터널로 되돌린다 |
| 산출물이 낡는다 | `meta.json` 시각이 하루 이상 밀린다 | 봇 쪽 굽기 경로가 실패하고 있다. 로그를 본다 |

**4단계까지 가지 않아도 실패가 아니다.** 2단계(터널로 보는 읽기 전용 웹)만으로도
지금보다 낫고, 그 상태로 멈추면 공개에 따르는 위험이 전부 사라진다. 공개는 화면이
쓸 만하다는 확신이 선 뒤에 한다.

# 계획: 세력 행동 추정 (`market_actor`)

한 줄로: **공시와 시세만으로 설명되는 "큰돈의 흔적"을 하루 한 번 사람이 읽는
문장으로 만든다.** 새 LLM 호출 없이, 산술과 명시적 규칙만으로 한다.

## A-0. 무엇을 게시하는가

먼저 결과물부터 정한다. 아래는 형식을 확정하기 위한 **목업이고 수치는 예시다**
(실제 종목명 대신 자리표시자를 썼다).

```text
🕵️ 흔적 추정 · 08-20(수) 16:10 KST

━ 표시 등락률과 실제 매매가 어긋난 곳 ━
· 종목A (KOSDAQ, 20일 평균 거래대금 210억)
  표시 +7.2% = 갭 +5.9%p × 장중 +1.2%p  →  표시 상승의 83%가 장 밖
  전일 종가는 당일 저가 +0.4% 지점(위치 0.04), 거래량 20일 중앙값의 2.1배
  전일 종가 대신 전일 대표가(고저종 평균)를 분모로 쓰면 +3.1%
  최근 10거래일 중 3번째 같은 형태 · 근거 5/5 → 신뢰도 상
· 종목B (KOSPI) — 역방향. 표시 -5.1% 중 갭 -4.4%p, 장중 -0.7%p · 근거 3/5

━ 돈이 어디로 옮겨갔나 ━
· 소형−대형 -1.4%p(z -2.1), 신용−국채 -0.8%p(z -1.7) → 같은 방향 2축
  위험에서 안전으로. 코스닥 -1.9% / 코스피 -0.6% / 항셍 +0.3%

━ 창구(중국 용호방, 08-19) ━
· 종목C 600XXX 매수 상위 5곳 중 机构专用 2곳 2.3억元, 매도 1위 개인 통로
  → 기관 창구 우위 · 미분류 1곳

지난 30일 이 형태 뒤 다음날 장중: 중앙값 -0.9%p(시장 대비), 표본 34, 하락 62%
관측된 수치와 그 산술 분해다. 매매 주체와 의도는 확인된 사실이 아니다.
```

마지막 두 줄이 이 기능의 핵심이다. **"세력이 무엇을 했나"보다 "그 형태 뒤에
무슨 일이 있었나"가 읽을 가치를 만든다.** 그 줄을 채우려면 A-8의 검증 루프가
먼저 돌아야 하므로, 단계 순서도 그렇게 짰다.

## A-1. 답하려는 질문은 둘뿐이다

1. **오늘 돈이 어디에서 어디로 옮겨갔나** — 시장·섹터 축.
2. **표시된 숫자와 실제 매매가 어긋난 곳은 어디인가** — 종목 축.

두 번째가 이 기능을 만들게 된 이유다. 등락률은 `오늘 종가 ÷ 전일 종가 − 1`이라
**분모도 분자도 종가 한 점**이고, 그 사이 시간(시간외·동시호가·다음날 시초가)은
등락률에 통째로 들어가지만 장중 매매로는 보이지 않는다. 그래서 마감 직전에 종가를
저가권으로 눌러 두면 다음날은 시초가만으로 큰 상승률이 만들어지고, 정규장에서
조금만 올려도 화면에는 강한 상승세로 표시된다. 실제로 장중에 산 사람이 얻은 것과
표시된 숫자가 다르다.

**이 어긋남은 주체를 몰라도 산술로 정확히 계산된다.** 그게 A-5의 전부이고, 이
기능이 추측이 아니라 계산인 지점이다.

## A-2. 서술 규칙 — 이것부터 못박는다

| 쓴다 | 쓰지 않는다 |
|---|---|
| 관측치와 그 산술 분해 | 의도 단정("주가를 조작했다", "세력이 말아올렸다") |
| 공시로 주체가 드러나는 시장의 창구 유형 | 데이터에 없는 주체 추정("외국인이 샀을 것이다") |
| 근거 개수로 매긴 신뢰도 등급(상·중·하) | 확률 수치("조작 확률 73%") |
| 과거 같은 형태의 실측 결과 | 매매 신호·목표가·추천 |

이유는 안전 문구가 아니라 **설계 제약**이다. 데이터에 없는 주체를 문장에 넣는
순간 그 문장은 검증할 수 없고, 검증할 수 없으면 A-8의 적중률 표에 한 줄도
쌓이지 않는다. 즉 지어낸 주체는 이 기능의 유일한 품질 장치를 무력화한다.
`polymarket_rules.py`가 방향을 LLM에 묻지 않고 allowlist로만 정하는 것과 같은
이유다.

고정 꼬리말 한 줄은 메시지 생성기가 **항상** 붙인다(옵션으로 만들지 않는다).

## A-4. 0단계 — 확인해야 답이 갈리는 것 셋

확인에 쓴 스크립트는 남기지 않는다(일회성이다).

## A-5. 축 A — 표시 등락률 분해 (종목)

기호: 전일 종가 `C₋`, 전일 고가 `H₋`, 전일 저가 `L₋`, 오늘 시가 `O`, 종가 `C`.

| 값 | 식 | 뜻 |
|---|---|---|
| 표시 등락률 `R` | `C / C₋ − 1` | 화면에 뜨는 숫자 |
| 갭 `G` | `O / C₋ − 1` | 장 밖에서 생긴 몫 |
| 장중 `I` | `C / O − 1` | 정규장 매매로 생긴 몫 |
| 종가 위치 `P₋` | `(C₋ − L₋) / (H₋ − L₋)` | 0이면 저가 마감, 1이면 고가 마감 |
| 분모 효과 | `R − (C / TP₋ − 1)`, `TP₋ = (H₋+L₋+C₋)/3` | 전일 종가 위치가 오늘 표시 숫자에 보탠 몫 |

`1+R = (1+G)(1+I)`이므로 표시 상승은 두 몫의 곱이다. 화면에는 `G`와 `I`를 %p로
나란히 적고 교차항은 무시한다(일간 변동 크기에서 0.1%p 미만).

**패턴 A(눌린 종가 → 갭업)** — 다섯 조건을 모두 본다.

1. `P₋ ≤ 0.15` (전일 종가가 당일 범위 하위 15%)
2. 전일 거래량 ≥ 20일 중앙값 × 1.5
3. `G ≥ +2.0%p`
4. `R ≥ +3.0%`
5. `I ≤ 0.4 × R` (표시 상승의 60% 이상이 장 밖)

유동성 하한(20일 평균 거래대금 30억원)을 먼저 걸어 호가 두세 개로 움직이는
종목을 뺀다. 이 하한이 없으면 목록이 매일 초저유동성 종목으로 채워져 아무도 읽지
않는다.

**역패턴 A′** 도 같이 본다(`P₋ ≥ 0.85`, `G ≤ −2.0%p`, `R ≤ −3.0%`, `|I| ≤ 0.4|R|`).
상승만 보면 절반을 놓치고, 하락 쪽 되돌림이 실제로 더 자주 보인다.

**반복성**: 최근 10거래일 중 같은 형태가 몇 번인가. 2회 이상이면 근거 1개 추가.
우연히 한 번 그런 날이 나오는 것과 같은 종목이 반복하는 것은 다른 이야기이고,
읽는 사람이 실제로 궁금해하는 것은 후자다.

신뢰도 = 충족 근거 수(조건 5개 + 반복성 + S2/S3가 되면 각 1개). 등급만 적고
확률로 바꾸지 않는다.

## A-6. 축 B — 돈이 어디로 옮겨갔나 (시장)

바스켓은 한 번의 배치 조회로 끝난다: `SPY QQQ IWM XLK XLY XLP XLU XLE XLF XLV
HYG TLT GLD UUP` + `^KS11 ^KQ11` + 중화권 지수. 60거래일치면 충분하다.

| 스프레드 | 정의 | 읽는 방향 |
|---|---|---|
| 소형−대형 | `IWM − SPY` | 음수면 위험 축소 |
| 성장−방어 | `(XLK+XLY)/2 − (XLP+XLU)/2` | 음수면 방어 선호 |
| 신용−국채 | `HYG − TLT` | 음수면 위험 회피 |
| 코스닥−코스피 | `^KQ11 − ^KS11` | 음수면 국내 위험 축소 |

각 스프레드의 당일 값을 60일 평균·표준편차로 z화한다. **`|z| ≥ 1.5`인 것만
문장으로 만들고, 같은 방향이 2개 이상일 때만 "이동"이라고 쓴다.** 하나만 튀는 날은
"뚜렷한 이동 없음"으로 적는다 — 매일 억지로 서사를 만들면 그 서사가 아무 뜻도
없어진다.

여기에 시장별 당일 등락률을 붙이면 "어느 장이 어땠으니"가 채워진다. 중국은 이미
있는 업종 보드와 涨停 수를 그대로 쓴다(새 조회를 늘리지 않는다).

## A-7. 축 C — 창구 유형 (중국 용호방)

`QuoteService.get_lhb_hits`는 관심종목만 걸러 4개 필드만 남긴다. 축 C는 **거래대금
상위 N개 종목**의 매수·매도 상위 영업부까지 본다(하루 10회 남짓의 추가 조회).

영업부 이름 → 유형은 `features/market_actor/desks.py`의 **명시적 allowlist**로만
정한다: `机构`(机构专用), `개인 통로`(拉萨 계열 등 알려진 개인·자동주문 창구),
`단기 자금`(이름이 알려진 游资 영업부), `미분류`. LLM에 묻지 않는다 — 이름 매칭은
규칙으로 끝나고, 규칙이면 왜 그렇게 분류됐는지 나중에 답할 수 있다.

판정은 셋뿐이다. **매수 상위에 机构 2곳 이상 + 매도 상위에 개인 통로** → `기관 창구
우위`. 반대 배치 → `개인 이탈 우위`. **미분류가 상위 5곳 중 3곳 이상이면 판정하지
않는다**(모르는 것을 아는 것처럼 쓰지 않는다). 미분류 개수는 문장에 그대로 적는다.

## A-8. 검증 루프와 승격 게이트

게시한 추정마다 다음을 남긴다: 날짜, 축, 종목, 충족 근거, 그리고 **다음 거래일의
장중 수익률**(`C₊/O₊ − 1`). 왜 장중인가 — 갭으로 만들어진 표시 상승이 실제 매수
흐름이면 다음날 장중도 버티고, 되돌림이면 장중이 음수다. 다음날 표시 등락률을 보면
같은 착시를 한 번 더 세는 꼴이 된다.

기준선은 **같은 날 같은 시장 전체의 장중 수익률 중앙값**이다. 시장이 통째로 빠진
날의 -1%는 이 형태와 무관하다.

| 게이트 | 값 | 통과하면 |
|---|---|---|
| 표본 | 축별 30건 이상 | 실측 줄을 게시 문장에 붙일 자격 |
| 방향 | 시장 대비 초과수익률의 부호 일치율 60% 이상 | 같음 |
| 가동 | 최근 30일 중 축이 비는 날 3일 이하 | 브리핑 편입·웹 게시 후보 |

셋을 모두 넘기 전에는 **텔레그램 전용**으로 남긴다. 웹(1~7절의 3-2 굽기 대상)에
올리는 것은 그 뒤다 — 검증되지 않은 종목 지목을 공개 화면에 먼저 올릴 이유가 없다.

`/system actor`가 이 표를 그린다. `/system prefilter`·`/system polymarket`과 같은
자리이고 같은 역할이다: **승격 근거를 화면 하나로 만든다.**

**이 검증이 답하지 못하는 것**(구현 시 `service.py` 첫머리에 상수로 적고, 지운 채로
승격하지 않는다):

- 형태가 나온 종목만 라벨이 붙는다. 조건에 못 미쳐 걸러진 종목이 그 뒤 어땠는지는
  관측되지 않으므로, 적중률은 "이 형태의 사후 분포"이지 "형태를 골라내는 능력"이
  아니다.
- 다음날 장중 약세가 나와도 그것이 **누가** 무엇을 해서인지는 이 자료로 알 수 없다.
  적중률이 높아지는 것과 주체 추정이 맞는 것은 다른 명제다.

## A-9. 배치·설정·예산

```text
app/features/market_actor/
  feature.py     FeatureSpec(명령·메뉴·callback·job 한 곳)
  decompose.py   축 A 순수 함수(OHLC → R·G·I·P·분모효과·패턴 판정)
  rotation.py    축 B 순수 함수(스프레드·z)
  desks.py       축 C 영업부 allowlist와 유형 판정
  service.py     취득·조립·검증 로그·보고서 생성
  handlers.py    /actor, /system actor 화면
```

| 항목 | 값 | 근거 |
|---|---|---|
| 기능 키 | `market_actor` · `requires={instruments, quant, watchlist}` | 종목명은 종목 DB, 시세는 `QuoteService`, 관심종목은 강조 표시에 쓴다 |
| 카탈로그 위치 | `signal_scoring` 앞 | 의존 순서(정량·관심종목 뒤, 집계 앞) |
| 상태 파일 | `data/market_actor/actor_log.jsonl`(검증용 append), `last_report.json`(마지막 화면) | 쓰임이 다르다. 리서치의 `history`/`last_result`와 같은 이유로 합치지 않는다 |
| 보존 | 90일 | 게이트가 30일·30건을 보므로 여유 3배 |
| env 키 | `MARKET_ACTOR_POST_ENABLED`(기본 `false`), `MARKET_ACTOR_POST_HOUR`/`MINUTE`(16/10) | 운영자가 조정하는 것만 env. 임계값은 전부 `config.py` 리터럴 상수 |
| 스케줄 | 하루 1회 16:10 KST | KR 15:30·CN 15:00(=KST 16:00) 마감 뒤, 미국은 그 시점에 전일분이 이미 확정 |
| Neurons | **0** | 문장은 템플릿이다. 모델은 의도를 지어내고, 그러면 A-8이 무너진다 |
| CPU | 하루 1회 수 초 | 사전선별 예산(3.6h) 밖의 여유 안. 실측 후 다시 본다 |

지켜야 하는 기존 규약: 시각은 `core/clock.py`의 `now()`·`today()`만(ruff `DTZ`),
저장은 `core/storage.py`의 원자적 쓰기만, 저장 실패를 로그로 삼키지 않는다,
텔레그램 문자열은 **절단 뒤 escape**(뒤집으면 `&amp;`가 끊겨 메시지가 거부된다),
축 하나의 실패가 나머지 축을 막지 않도록 축 단위로 격리한다(뉴스 소스 격리와 같다).

검증 로그는 하루 20줄 남짓이라 90일치가 2천 줄이다. **사전선별 관측과 달리 offset
이어 읽기가 필요 없다** — 그쪽이 그렇게 된 것은 하루 10만 줄이기 때문이고, 같은
구조를 이유 없이 복제하지 않는다.

한국 휴장일 판단에 새 캘린더를 만들지 않는다. 그날 시세 행이 없으면 휴장으로 보고
조용히 건너뛴다(`briefing/calendar.py`는 A주 기준이라 한국 휴일과 다르다).

테스트(`tests/test_market_actor.py`)는 순수 함수 위주로 둔다: 분해 산식이 `1+R =
(1+G)(1+I)`를 만족하는가, `H₋ = L₋`(상한가 등 범위 0)에서 `P₋`가 죽지 않는가,
다섯 조건 중 넷만 맞을 때 패턴이 안 잡히는가, 역패턴 대칭, 미분류 3곳이면 축 C가
판정을 비우는가, 표본 부족일 때 실측 줄이 빠지는가. 외부 조회는 전부 mock한다.

## A-10. 단계

각 단계는 **그 단계까지만 하고 멈춰도 안전한** 상태로 끝난다.

- **0단계 — 자료 확인.** A-4의 세 줄을 확정해 이 문서에 적는다. 코드 없음.
- **1단계 — 계산기.** `decompose.py`·`rotation.py`·`desks.py`와 테스트. 취득도
  게시도 없다. *완료 기준*: 고정 입력에 대한 판정이 테스트로 고정되고 ruff·pytest 통과.
- **2단계 — `/actor`.** 요청할 때만 계산해 화면을 그린다. 예약 게시 없음
  (`MARKET_ACTOR_POST_ENABLED=false`). *완료 기준*: 실제 오늘 자료로 세 축이 그려지고,
  자료가 없는 축은 그 축만 빠진다.
- **3단계 — 예약 게시와 검증 로그.** 16:10 job, `actor_log.jsonl` 적재, 다음 실행
  때 D+1 채우기. *완료 기준*: 이틀 연속 돌린 뒤 로그의 D+1이 채워져 있다.
- **4단계 — `/system actor`.** 축별 표본·부호 일치율·가동률 표. *완료 기준*: 게이트
  세 줄이 화면에서 바로 읽힌다.
- **5단계 — 승격.** 게이트를 넘긴 축만 실측 줄을 붙이고, 브리핑 편입과 웹 굽기를
  검토한다. **넘지 못하면 그 축은 텔레그램에 그대로 둔다. 그것도 결과다.**

## A-11. 하지 않기로 한 것

- **LLM에 추정을 맡기지 않는다.** 모델은 근거 없이도 그럴듯한 주체와 동기를 채워
  넣고, 그 문장은 검증할 수 없다. Neurons 문제 이전에 품질 문제다.
- **분봉·틱·호가 기반 추정.** 자료원도 CPU 예산도 없다. 일봉 경계에서 답할 수 있는
  것만 답한다.
- **매매 신호·목표가·추천.** 이 기능은 관측 보고이지 조언이 아니다.
- **주체를 모르는 시장에서 주체를 말하기.** S2가 실패하면 KR은 행위만 적는다.
- **HK 축.** 창구·수급 자료가 없다.
- **KONEX·저유동성 종목.** 20일 평균 거래대금 하한 아래는 보지 않는다.
- **검증 전 웹 게시.** A-8 게이트 통과가 선행 조건이다.
- **새 문서 파일.** 이 계획은 여기 남고, 끝나면 지운다.

## A-12. 위험과 중단 기준

| 위험 | 신호 | 조치 |
|---|---|---|
| 자료원 컬럼 변경(FDR·AkShare) | 축이 조용히 빈다 | 축 단위 격리로 나머지는 게시된다. 30일 중 3일 넘게 비면 그 축을 끈다 |
| 오탐이 반복된다 | `/system actor`의 부호 일치율이 50% 근처에 머문다 | 임계값을 손대기 전에 표본을 더 모은다. 60일 넘게 개선이 없으면 그 축을 뺀다 |
| 목록이 매일 같은 잡주로 찬다 | 유동성 하한이 낮다 | 하한을 올린다. 상한을 축당 3종목으로 유지한다 |
| 문장이 단정으로 흐른다 | 템플릿에 "조작·세력이 ~했다"가 들어간다 | A-2 표로 되돌린다. 꼬리말은 옵션이 아니다 |
| CPU가 는다 | 사전선별 로그에 `중단=budget`이 새로 늘어난다 | 축 C의 개별 조회 수를 줄인다(가장 비싼 부분이다) |

**2단계(`/actor` 명령)까지만 가도 실패가 아니다.** 요청할 때만 계산하는 화면
하나로도 A-1의 두 질문에 답이 되고, 그 상태에서는 잘못된 추정이 예약 게시로
반복될 위험이 없다. 자동 게시는 화면이 쓸 만하다는 확신이 선 뒤에 켠다.
